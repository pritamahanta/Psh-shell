1.  What is a shell ? 
->  A shell is a program that interprets commands and interacts with the os kernal 

2.  When you type a command, the shell:

->  1. Reads the command
    2. Parses it
    3. Executes the program using system calls (fork, exec, etc.)

3.  What is a terminal ? 

->  A terminal is a program that provides a text interface to interact with the shell. 
    it's basically a window where we type commands and see outputs 

4.  What is sigaction ? 
->  struct sigaction is a data structure used in Unix/Linux systems todefine how 
    a process handles signals (like SIGINT, SIGTERM, SIGSEGV, etc.). It's a part of the POSIX signal handling API

    struct sigaction {
        void (*sa_handler)(int);      // Pointer to signal handler function
        void (*sa_sigaction)(int, siginfo_t *, void *); // Advanced handler
        sigset_t sa_mask;             // Signals to block during handler execution
        int sa_flags;                 // Special behavior flags
    };

5.  which process group can use terminal ? 
->  Only the forground process group is allowed to use the terminal.
    If a background process group tries -> OS intervenes using signals.

6.  What is a Built-in command ? 
->  Built-in commands are executed by the shell itself (parent process),
    whereas external commands require creating a child process and using exec() to run the executable.


7. What is and REPL loop ? 

->  A REPL (Read-Eval-Print Loop) is an interactive coding environment. It reads user input,
    executes (evaluates) the code, prints the result, and loops back to wait for the next command. 
    It is primarily used for quick testing, debugging, and experimenting with programming languages like Python, JavaScript (Node.js), or Ruby.

8.  What is tcsetpgrp() ? 

->  tcsetpgrp() is a POSIX standard C library function used to set the foreground process group ID (PGID) associated with a controlling terminal. 
    It is primarily used by command-line shells (like Bash or Zsh) to implement job control, 
    giving a specific process group direct access to read from and write to the terminal.

9.  Every terminal has how many foreground process group ? 

->  Every terminal has one foreground process group. The kernel keeps track of which process group currently owns the terminal.
    Only the foreground process group is allowed to freely interact with the terminal.

10. Volatile qualifier 

->  This variable may change unexpectedly. Always read it from memory. Never cache it in a register.

11. sig_atomic_t
