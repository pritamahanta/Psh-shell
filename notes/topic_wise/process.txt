1. Can We Place a Child Process into Any Other Process Group?
=============================================================

No.

A child process cannot be placed into just any arbitrary process group.

POSIX-compliant operating systems (such as Linux) enforce strict rules to prevent one application from interfering with another. 
These restrictions ensure process isolation, security, and proper job control.

The Rules of setpgid()
----------------------

When using:

    setpgid(pid, pgid);

the following rules apply:

Rule 1: The Target Process Group Must Belong to the Same Session
---------------------------------------------------------------

The process group identified by `pgid` must already exist within the same session as the calling process.
A session is typically created when you log into a terminal and contains one or more process groups.

Example:

Session A
├── Process Group 100
├── Process Group 200
└── Process Group 300

A child process inside Session A may join Process Group 100, 200, or 300.

------------------------------------------------------------

Rule 2: The Child May Create Its Own New Process Group
------------------------------------------------------

Instead of joining an existing group, the child can become the leader of a brand-new process group.

Example:

    setpgid(0, 0);

Meaning:
- The calling process (the child) uses its own PID as the process group ID (PGID).
- The child becomes the leader of a new process group.

This is the most common behavior used by shells when launching a new command.

------------------------------------------------------------

Rule 3: A Process Cannot Join a Process Group in Another Session
----------------------------------------------------------------

A process is NOT allowed to join a process group that belongs to a completely different session.

Example:

Session A
├── PGID 100
└── PGID 200

Session B
├── PGID 500
└── PGID 600

If a child process belongs to Session A, it cannot join PGID 500 or PGID 600 because they belong to Session B.

The kernel rejects such a request.

Reason:
- Prevents applications from hijacking or interfering with processes running in another terminal or login session.
- Maintains process isolation and security.

------------------------------------------------------------

Why Does POSIX Enforce This?
----------------------------

These restrictions exist to:

- Prevent one application from controlling another application's processes.
- Prevent unauthorized terminal access.
- Maintain secure process isolation.
- Ensure correct job-control behavior in Unix/Linux systems.

------------------------------------------------------------

Summary
-------

A child process can:

✓ Join an existing process group within the same session.
✓ Create a new process group and become its leader.

A child process cannot:

✗ Join a process group belonging to another session.
✗ Join an arbitrary or unrelated process group.

------------------------------------------------------------

Key Takeaway
------------

`setpgid()` is restricted by session boundaries.

A child process may either:
1. Join an existing process group in its current session, or
2. Create a new process group of its own.

It cannot join process groups that belong to a different session, ensuring security and proper process isolation.
